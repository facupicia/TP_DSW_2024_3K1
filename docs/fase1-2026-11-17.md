## Cambios

- Las lecturas de una suscripción activa ya no bloquean la fila del organizador.
  Crear o reemplazar una suscripción sigue serializando las escrituras y conserva
  los índices de unicidad existentes.
- El checkout usa el ID de cupón congelado en PostgreSQL. La entrega consume un
  uso mediante un único UPDATE que comprueba evento, activación, vencimiento y
  límite. Un pago que pierde el último uso, o cuyo cupón dejó de estar disponible,
  conserva una solicitud durable de devolución sin entregar entradas ni extras.
  El consumo se revierte junto con el stock si falla la entrega.
- Los códigos de cupón son únicos por evento, tanto en la API como en PostgreSQL.
- Outbox pasa a fallo definitivo tras 12 intentos fallidos. `failedAt`, el payload,
  la clave de idempotencia y el error se conservan para revisión y reintento manual.
  `/api/admin/operations` distingue estos fallos de los trabajos pendientes. El
  reintento de devoluciones también limpia `failedAt`.
- Las notificaciones `pending`, `in_process`, `authorized` e `in_mediation` se
  confirman sin repetir infinitamente la misma notificación. Una nueva notificación
  conserva su propia clave y puede procesar un cambio posterior del mismo pago.
- Fuera de sandbox, la consulta del webhook prueba primero el organizador conocido.
  Sandbox mantiene su aislamiento de las credenciales reales de organizadores.
- `/health` precede al limitador global y sigue comprobando PostgreSQL. Los límites
  globales, de login y de refresh mantienen un contador local durante fallas de
  Redis, con espera máxima de 500 ms y pausa de 5 s entre intentos de recuperación.
  El contador local también recibe las solicitudes anteriores a la falla. Durante
  una caída de Redis, el límite compartido entre réplicas se degrada a uno por proceso.
- Admin y logout devuelven errores genéricos. El registro interno conserva mensaje
  y stack; el error global omite la query string de la URL registrada y oculta
  también los códigos internos de errores 500 al cliente.
- El seed de volumen ejecuta ANALYZE después de completar y verificar la carga.

## Migración y operación

`PhaseOneHardening1794956400000` agrega `outbox_job.failedAt`, reemplaza la unicidad
global de cupones sin reescribir filas y crea estos índices:

- `ticket("paymentLogId")`.
- `event_product("productId")`.
- `user_subscription("planId")`.
- `checkout_order("eventId") WHERE status='pending'`.

La migración se ejecuta explícitamente durante el release, con `DB_SYNC=false`.
Su reversión se niega a borrar el estado de trabajos fallidos o a forzar códigos
globalmente únicos cuando ya existen cupones del mismo código en distintos eventos.

Para revisar los trabajos detenidos, consultar `outbox_job` por `failedAt IS NOT NULL`.
Después de corregir la causa, reintentar una devolución mediante el endpoint admin
existente. Para otros trabajos, un operador puede limpiar `failedAt` y `lastError`,
reiniciar `attempts=0` y fijar `availableAt=NOW()` sobre el ID específico, comprobando
que no exista un lease vigente. Conservar el payload y la clave original.
